Why one template covers both

Two structures, one vocabulary

A song has a shape on disk and a shape in time, and they are easy to let drift apart. Here they share one set of names, so a folder tells you where you are in the song and a scene tells you which file to look for.

Shape in time

Seven sections, 104 bars. Every section is a multiple of 8 — which matters because the bed is 8 bars, so any bed loops cleanly into any section without a cut.

Section names double as Live scene names and as the terminals the arrange grammar expands to.

Shape on disk

One folder per song holding the Live set, the beds, the layer bundles pulled from Move, and the renders. Plus SONG.md — tempo, key, the form table, and a log of which bed each part was played against.

Created by new-song.sh, so it is identical every time.

The shape is deliberately conventional: build, state, lift, drop out, pay off, restate, leave. The value is not originality — it is that you never start from a blank arrangement, and the break at bar 48 is decided before you have written a note.

The break is the point

BREAK is the only section shorter than 16 bars and the only one that drops energy sharply. It exists so B′ lands. If a song feels flat, the break is usually too long, too busy, or missing.

The useful half of the template

Who plays where

This grid is how the "everybody rests" rule gets enforced. Playing parts one at a time, alone, produces layers that play constantly — here you decide in advance where each one stops.

Read it down a column

A layer with ● in every row is playing too much and will need thinning at mix time — which is late. L5 atmosphere is the deliberate exception: it plays throughout because it is the room, not a part.

Note L3 rhythm drops out in A′ so the lead has space, and L4 lead is silent for the first 48 bars.

Read it across a row

A section with everything on has nowhere left to build. Only B′ is full, which is what makes it the payoff.

Energy tiers move by one step between neighbours except into and out of BREAK — those jumps are the two deliberate discontinuities in the song.

This is a default, not a law. Change it per song in that song's SONG.md — but change it deliberately, and before tracking, not after.

One folder per song

On disk

/Volumes/Bisonte/Music Project/Bisonte/ └── <Song> Project/ ├── <Song> v01.als the accumulating Live set ├── SONG.md tempo, key, form, tracking log ├── Beds/ bed_v01…v06.wav — 8 bars each ├── Parts/ layer bundles pulled from Move │ ├── <Song> L1 drummer.ablbundle │ └── <Song> L2 bassist.ablbundle ├── Samples/ Live-managed, do not hand-edit ├── Ableton Project Info/ └── Renders/ ├── master/ the mix ├── stems/ one per layer group └── seeds/ loops + one-shots pushed back to Move

Two folders are new relative to the old playbook layout. Beds/ holds the headphone mixes, one per layer committed. Parts/ holds the bundles as pulled — the last state Move and Live share, and the thing to go back to when a part needs re-tracking.

Scaffolded, not hand-made

new-song.sh creates this exact skeleton every time, so no song is missing a folder and none of them drift apart. Override the root with BISONTE_PROJECTS if projects ever move.

When to bump

Versions

Rules

  • v01 → v02 at every structural change — a layer lands, a section is added or cut.
  • v02b for a mix alternative of the same structure.
  • Use Save a Copy so the project folder stays shared.

Readable history

Live Sets are gzipped XML, so git diff can show what actually changed between versions once the textconv filter is on:

git config diff.als.textconv 'gunzip -c'

A renamed generated clip shows up as one line of XML — which is what makes the seeded naming scheme pay off.

Two commands

Starting a song

# scaffold folders + SONG.md with the form table
tools/new-song.sh "Bisonte Club 2" 124 "F minor"

# then, on Move: new Set named "Bisonte Club 2 L1 drummer" at 124 BPM
# L1 is the only part tracked with no bed — it is the first bed.

After L1 is committed to Live, render bed_v01.wav into Beds/, push it to Move, and the loop from the Layer Stack Method takes over for L2 onward.

Fill these in before tracking

SONG.md ends with three blanks that are worth answering out loud: the kick/bass relationship, what only this track has, and the reference record. All three are cheap to decide now and expensive to discover at mix time.
